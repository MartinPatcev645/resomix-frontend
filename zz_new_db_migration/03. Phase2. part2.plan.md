### What Needs to Change (Imports + Column/Relationship References)

**Broken imports (line 25-28):**
- `from app.models.recording_artist import RecordingArtist` → **`from app.models.track_contributor import TrackContributor`**
- `from app.models.artist import Artist` → **`from app.models.contributor import Contributor`**
- `from .genre import Genre` → **`from app.models.genre import Genre`** (import was always wrong)
- `from .constants import TrackType` → **`from app.models.constants import TrackType`** (import was always wrong)

**Columns that no longer exist on `Track`:**
- `file_path` — No longer on tracks. Stored in `audio_files.stored_path`. Used in: `get_track_path_by_uuid()`, `search_tracks()`, `async_get_tracks_by_file_paths()`
- `duration_sec` — Renamed to `duration_ms`. Used nowhere directly in this file.
- `preview_path` — No longer on tracks. Not directly referenced.

**Relationships that no longer exist on `Track`:**
- `track.label` — No longer a direct relationship. Labels are on releases.
- `track.genre` — No longer a relationship object. Genre is now a string field `track.genre`.
- `track.recording_artists` → now `track.recording_contributors` (→ `TrackContributor`)

> [!CAUTION]
> **Business Logic Behavioral Change**: Several methods currently return data from `track.label`, `track.genre`, and join through `RecordingArtist→Artist`. In the new schema, there is no `track.label` and no `Artist` model. The equivalent data paths are:
> - **Label**: `Track → release_assocs → Release → label`
> - **Genre**: `track.genre` is now a plain string field — no join needed
> - **Artist info**: `Track → recording_contributors → TrackContributor → contributor` (the `Contributor` model replaces `Artist`)
> 
> **This DOES change the output shape** of methods like `search_tracks()`, `get_with_relationships()`, and `async_get_tracks_by_file_paths()`. The search results will no longer include `label` unless we add a multi-hop join through releases.

### Proposed Approach (Preserving Behavior)
1. Fix all broken imports
2. Replace `RecordingArtist` → `TrackContributor`, `Artist` → `Contributor` in joins
3. Replace `track.recording_artists` → `track.recording_contributors` in attribute access
4. For `file_path` references: join through `AudioFile` where needed
5. For `label` references: use `track.display_artist` or join through `release_assocs → release → label` as a best-effort
6. For `genre` references: use `track.genre` as a string directly (no join needed)
7. **NOT** delete any methods — only update their internals

## 3. `similarity_repository.py` — HIGH Sensitivity (Core Product)

### Current Business Logic (364 lines)
This is the **heart of the product** — the similarity engine's data layer.

| Method | What It Does | Problem |
|---|---|---|
| `async_get_reference_track_details_by_path()` | Raw SQL: joins `tracks←labels`, `tracks←recording_artists←artists` by `file_path`/`preview_path`. Returns `{id, title, year, duration, label, artist, type}` | Uses `duration_sec`, `label_id`, `file_path`, `preview_path`, `recording_artists`, `artists` |
| `async_get_reference_track_details_by_uuid()` | Same but by UUID | Same issues |
| `async_get_track_details_by_paths()` | Calls `TrackRepository.async_get_tracks_by_file_paths()`. Accesses `track.recording_artists`, `track.label`, `track.duration_sec`, `track.file_path`, `track.year` | All legacy attributes |
| `async_get_track_details_by_uuids()` | Calls `TrackRepository.async_get_tracks_by_uuids()`. Same accesses. | All legacy attributes |
| `async_update_track_duration()` | Raw SQL: `UPDATE tracks SET duration_sec = :duration` | Column renamed to `duration_ms` |

> [!WARNING]
> **This is the most dangerous file to edit.** Every method returns a specific dictionary shape that the similarity service and API layer consume. The keys (`id`, `title`, `year`, `duration`, `label`, `artist`, `type`) MUST remain identical. Only the internal query mechanics change.

### Proposed Approach
1. **Raw SQL queries**: Rewrite JOINs to use `track_contributors` + `contributors` instead of `recording_artists` + `artists`. Use `audio_files.stored_path` instead of `tracks.file_path`.
2. **Duration**: `duration_sec` → compute from `duration_ms / 1000.0` in the SELECT to keep returning seconds to the API.
3. **Label**: Join through `release_tracks → releases → labels` instead of direct `tracks.label_id`.
4. **Year**: Use `tracks.p_line_year` (same column name, still exists).
5. **Output shape**: Keep every dictionary key identical.
6. `async_update_track_duration()`: Update to write `duration_ms` (convert incoming seconds → ms).
