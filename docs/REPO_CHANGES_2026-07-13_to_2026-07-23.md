### 🐛 Bug Fixes  *(several are one-liners with large real-world impact)*

- **Background audio + runaway HLS requests on navigate-away** (`81d949f`, "SENSITIVE HLS PLAYBACK
  UPDATE"): the global audio singleton kept the `<audio>` playing and kept firing HLS
  segment/session/**retry** requests after leaving the playlist page. Now `AudioProvider` calls
  `controller.unload()` on unmount (stops audio + tears down the stream and retry/cold-retry timers);
  AnalysisPage pauses its local `<audio>` on unmount too.
- **All-preview (catalogue) playlists had a dead progress bar / seek** (`c65634e`, 6 lines): core
  `<audio>` events (`timeupdate`, `ended`, …) were only bound inside the HLS path, so a playlist
  where every track plays from an Apple preview never bound `timeupdate` → elapsed/duration/seek
  stayed frozen while audio played. Now bound up-front (idempotent).
- **Player freeze on mixed (HLS-seed + preview) playlists** (`41ec023`): one-shot `canplay`/`seeked`
  listeners from a superseded source could fire against the new one, and a preview member reached via
  the media-session next/prev could seek the HLS seed stream past its end and wedge. Fix: one-shot
  listener teardown + `resetSeekState()` on every track/mode switch, and route preview members to the
  preview loader instead of seeking the HLS stream.
- **HLS/preview single-element race → CORS breakage** (`2730e49`): reworked to **two dedicated
  `<audio>` elements** (hls.js-owned `crossOrigin='anonymous'` for peaks/Web-Audio; a
  no-crossOrigin element for Apple's preview CDN), plus a monotonic load-generation guard against
  stale async callbacks and a snippet-loading grace period before the "Network" badge shows.
- **Playback dead after refresh / opening from Library** (`a5a8b36`): the HLS-attach effect fired
  once with a null `audioRef` (the `<audio>` mounts only after the dashboard renders) and never
  retried; it now also re-runs when the player mounts. Related: HLS retry/error recovery for
  transient session/network failures (`a6a6d73`), reset seed playback position (`07ef3b2`).
- **Cross-subdomain identity mismatch** (`5e1d981`): the refresh cookie is shared across
  `*.resomix.com` while tokens/users live in per-origin storage, so a login on one subdomain could
  leave another holding a token for a *different* user. Now the token's `sub` is checked against the
  persisted user and the server session is adopted as source of truth when they disagree (no-op /
  no request in the common case).
- **Logout on a flaky network** (`8131bef`): added an authoritative session check that distinguishes
  `valid` / `invalid` / **`network` (unknown)** and never logs the user out on a network error;
  concurrent callers share one in-flight refresh (the backend treats a reused refresh token as an
  attack). Also stopped downloading the heavy analysis result JSON twice when opening a finished
  analysis.
- **Guest "demo" teaser stuck after login** (`636fc6c`): auth flips cleared only the localStorage
  playlist cache, leaving the redacted anonymous copy in the in-memory store; `usePlaylistLoader`
  short-circuited on it so a logged-in user kept seeing the teaser. Now the store is `reset()` on
  login/logout to force a fresh, full refetch.
- **Stale playlist data across navigations** (`b6aaf7b`, `b83be1e`): `usePlaylistLoader` now refetches
  on URL `?id=` change and clears stale data reactively; request de-duplication guards React
  StrictMode double-invocation (`24e260b`).
- **"Playlist is Private" screen flashing during load** (`9b6385b`): view state is now derived
  directly from the store (data/error) instead of a lagging `isLoading`, so the private screen only
  appears on a definitive failure — not in the brief mount/redirect window.
- **Duplicate entitlements fetch** (`1bf3445`): concurrent `useAccess`/`useEntitlements` consumers
  fired a second request because dedup keyed on `cachedIdentity` (only set on resolve); now keyed on
  a synchronously-set `inflightIdentity`.
- **Apple Music badge shown on user uploads** (`b5139c1`): mobile gated on an unreliable `isUpload`
  flag and the badge fell back to Apple's homepage link; now gated on the server-provided
  `type === 'internal' && deep_link_url`, and the badge renders nothing without a deep link. Removed
  the deprecated `isUpload` field.
- **Auth redirect losing the target** (`0815be6`): post-auth redirect now preserves the full path +
  query across sessions via localStorage, with updated route guards.

### 🔧 Other / Small Changes

- **Shared utilities & refactors:** `shortGenre` (`de38e84`), `firstGenre` (`8696d41`), `displayOrNA`
  (`9c0e62c`), and library `trackMeta` helpers + `TrackMetaRow` (`4e1e663`); Profile settings state

  responsive artifact-chip stacking (`921d2c1`); `Error404` / `DemoStageBanner` refinements

- **Branding / copy:** "Demo Stage" → "Beta Stage" across configs + footers, Rename icon → inline SVG

- **Navbar:** restrict app-only links (Library/Analysis) to the app subdomain + dropdown navigation

- **Build / tooling:** `@resomix/stores` Vite path alias added across all three apps (`3d1d7c1`);

  conventions doc added to `instructions.md` (`8696d41`).
- **Navigation state:** cache Library origin so "Back" returns correctly from playlist/analysis

### 📋 Summary

The 10 days on `resomix-web` delivered **five major feature tracks** and a **deep pass on
playback + auth reliability**. Features: **Google sign-in**, full **Apple Music** integration
(badge/banner/preview player **and** playlist export to Apple), **Stripe billing/subscriptions**
(consumer + admin price management), a **Library workspace** (search/date/track-count filters,
favorites-as-filter, rename, public/private toggle, TXT/Apple export, artifact chips with background
polling), and the **custom playlist cover** (upload + canvas title overlay + unified thumbnails).
The analysis landing gained a recent-analyses preview and server-side HLS playback.

The bug-fix work is the higher-stakes half: the audio/HLS engine was substantially hardened —
**it no longer plays in the background or fires runaway retry requests after you navigate away**, the
**progress bar/seek work on catalogue (preview) playlists**, **mixed HLS+preview playlists no longer
freeze**, and HLS/preview were split onto **two audio elements to end CORS/rapid-switch races**.
Auth got a **cross-subdomain identity guard**, a **network-aware session check that won't log you out
on a flaky connection**, and fixes so **logging in no longer strands you on the guest teaser**. A
cluster of loader/entitlement fixes removed stale-data flashes and duplicate requests. Underpinning
it all, shared logic kept migrating into `packages/hooks`/`stores` (access gating, playback token,
profile settings, track-meta utils), keeping pages thin.

## 2 · `basic_fastapi_server_resomix` — Alwyzon Backend (FastAPI, layered)

**Window:** 2026-07-13 → 2026-07-23  ·  **Commits:** 54.
**Stack:** FastAPI + SQLAlchemy (async) + MariaDB + Redis + Celery; layered controllers → services →
repositories; multi-tenant (partner-scoped) with a SQL failsafe.

### 🚀 New Functionalities

- **Apple Music integration (the backend half of the catalogue-playback pivot):**
  - `AppleMusicTrack` model + `apple_music_tracks` table + ingestion scripts (matched-track insert,
    uuid backfill); `source_file_path` added to `Track` (`7a15301`).
  - **Playback enrichment**: joins Apple data (`preview_url`, `artwork_url`, `deep_link_url`,
    `apple_song_id`, isrc, and Apple-authoritative title/artist/album/genre) onto serialized tracks,
    with a `playback` hint (`preview` vs `hls`) (`37da292`); made **fault-tolerant** with full unit
    + redaction test coverage (`52a3ac4`); Apple prioritized for display + dynamic playlist-name
    re-derivation at serialization (`40c4b47`).
  - **Apple-first search**: index-time + read-time overrides so search shows Apple title/artist
    (`a978c23`).
  - **Apple Music playlist export/transfer**: persistent per-user account connections with
    **encrypted token storage** + new endpoints + migration (`8bbe920`); **batched ISRC→storefront
    resolution** (`8ecf6c2`); robust Apple API handling with **retry + batching** (`be2676e`);
    seed-based export naming + descriptive metadata + default cover art (`ece65c0`); seed track uuid
    surfaced in queries/response (`8ad22d8`).
- **Stripe consumer billing & subscriptions:** billing models + migrations + plan/purchase tables
  (`5948d5d`); checkout + customer-portal flows and a Pro-price seed script (`40fa749`);
  **`BillingSyncService`** handling subscription webhooks + endpoints for subscription summary &
  invoice history (`f2b7ea0`); **durable usage-history tracking** + retrieval API (`0236a7a`); admin
  **Stripe price-management** endpoints/service (`bae99ea`).
- **Google OAuth2 sign-in:** `/auth/google` ID-token flow, nullable password_hash migration for
  social accounts, and letting social users set an initial password (`e85f437`).
- **Elasticsearch rebuild pipeline:** zero-downtime reindex script + systemd service/timer
  (`c1ecd32`); dedicated **writer credentials** for reindexing (`e5e0abe`); `ELASTICSEARCH_ENABLED`
  toggle (`0544360`); a **`/search_health/`** connectivity endpoint (`76791a5`).
- **Library filters (backend):** search + date-range filtering for tracks *and* playlists, plus
  playlist `num_tracks` minimums (`52bf3db`), with test coverage (`14bfc71`); track serialization
  restructured to a **batch-resolved analysis + display-metadata** block, and release logic now
  persists track labels (`9c6d174`).
- **Custom playlist cover upload (backend):** authenticated upload endpoint with **magic-byte type +
  size validation + optional ClamAV scan**, a `has_custom_cover` column + migration, and
  `HetznerService` store/delete methods to the media server (`de5a240`); partner dependency added for
  tenancy validation (`0c3d914`); cover **cleaned up on playlist deletion** (`f1a1adc`).
- **B2B partner contact flow:** partner contact type + schema/migration + **confirmation emails**

- **Analysis ↔ HLS integration:** analysis responses enriched with the track + its **sibling

- **Ops / maintenance:** an operational **RUNBOOK** for the Alwyzon box (`effb564`); registered the
  `purge_uploaded_track_assets` Celery task (`d112f86`).

### 🐛 Bug Fixes  *(several one-liners with outsized impact)*

- **Thin analysis playlists (2–15 tracks)** (`7566c55`): the analysis sibling playlist fetched
  *exactly* `top_k` from the similarity server with no cushion, so after Apple-match de-dup only a
  handful survived. Now it **over-fetches `top_k + cushion` (e.g. 50) and keeps `top_k` (e.g. 20)**,
  mirroring the interactive path — consistent full-length playlists.
- **Silent playlist-creation failures** (`bd0978f`): the uploaded seed's DB id is now resolved via a
  partner-scoped/active lookup **with a plain uuid→id fallback** (a partner/`is_active` edge on the
  just-created upload was silently dropping its own playlist); the code no longer reports success when
  no playlist row was written, and logs exact `raw/enriched/dedup` counts.
- **Reference track shows 0:00 & is un-seekable after reopening** (`d8aa5b2`): the duration UPDATE
  was missing `partner_id`, so `WHERE uuid=… AND partner_id=NULL` matched **zero rows** and silently
  persisted nothing, leaving `duration_ms` NULL. Added the required `partner_id` + a fallback to the
  analysis result's duration.
- **HLS 404 from a doubled URL** (`0c6da68`): `hls_media_base_url` already ends in `/signed-audio/`,
  so re-prefixing produced `/signed-audio/signed-audio/hls-m3u8/` → 404. Made the endpoint relative.
- **Catalogue tracks broke the HLS manifest** (`060350a`): the server-stitched manifest now includes
  **only HLS-playable uploads** — catalogue members play from Apple previews client-side and have no
  segments.
- **Apple MusicKit `authorize()` rejecting the JWT** (`f57491b`): Apple developer tokens must contain
  **only `iss`/`iat`/`exp`**; a leftover `aud` claim triggered `ERROR_FAILED_TO_VERIFY_JWT` in the
  user-authorization flow (the read-only catalog API tolerated it, which masked the bug).
- **Duplicate welcome emails / non-idempotent verification** (`8b59c66`): the verify endpoint is
  re-hit by mail scanners / prefetch / refresh; the welcome email now fires **only on the first**
  verification and the token is no longer consumed, so repeat hits are safe no-ops.
- **Analysis expiry returned 502 instead of 404** (`97e3fd2`): upstream 404 (expired/missing
  analysis) is now mapped to a clean 404.
- **Missing artist in playlist rows** (`2071065`): falls back to `display_artist` when track
  contributors are absent.
- **Audio retrieval prefers master files** with a fallback (`effb564`).
- **`consumption_events.isrc` too short** — widened to `VARCHAR(30)` via migration (`d112f86`).
- **Stripe housekeeping:** adapt to Stripe API changes + route billing redirects through a new
  `APP_URL` (`e826cc2`); checkout success/cancel redirect to the profile page (`bc34550`).
- **Alembic migration bugfix** (`a514a99`) and a test fix (`fab86bc`).

### 🔧 Other / Small Changes

- **Apple `apple_song_id` + ISRC de-duplication** *(committed under the docs-titled `dbed37a` —
  message understates it):* `deduplicate_tracks` now fetches an Apple map by `track_id` and dedupes
  by **`apple_song_id` + ISRC before truncation** (so removals are absorbed by the cushion and the
  count holds), keying the fuzzy artist/title layer on **Apple's** values; a shared
  `dedupe_by_apple_identity` also cleans existing playlists on read. Same commit vendored the
  full-stack-quality skill as a git submodule + local settings.
- **Leaf-genre extraction** (`f02179d`): analysis summary stores the leaf of a `Parent---Child`
  Discogs genre (e.g. `Electronic---Deep House` → `Deep House`) at the save point.
- **Perf:** replaced correlated subqueries for track duration with a derived join (`30005f0`).
- **Tests:** playlist-filter tests (`14bfc71`), library-track analysis-block validation (`aee01cd`),
  sanitization-filter unit tests (`dd3fc09`), redaction tests, and billing unit tests (`0236a7a`).
- **Build / infra:** Makefile support for an embedded Celery worker + similarity logging (`e833840`);
  ES systemd paths, silenced ES logging, removed a stray `.env.bak` (`8b40b7e`).

### 📋 Summary

Alwyzon's 10 days were dominated by **three platform-scale additions** and a set of **high-impact
reliability fixes**. The additions: (1) the **Apple Music** backbone — ingesting matched Apple tracks,
enriching every serialized track with Apple metadata + preview playback, making catalogue search and
display Apple-first, and building the **playlist-export-to-Apple** transfer with encrypted account
connections, ISRC storefront resolution, and retrying batched API calls; (2) **Stripe consumer
billing** end-to-end — models, checkout/portal, webhook sync, usage history, and admin price
management; (3) the **Elasticsearch rebuild** pipeline with zero-downtime reindexing on a systemd
timer and a health endpoint. Alongside these: **Google OAuth**, backend **library filters**, the
**custom playlist-cover** upload/validation/cleanup, and a **B2B partner** contact/notification flow.

The bug fixes quietly protect core UX: playlists **stopped coming out thin** (over-fetch + dedup
cushion) and **stopped failing silently**; the reference track **no longer shows 0:00** after reopen
(a one-word `partner_id` omission was nulling durations); HLS manifests **stopped 404-ing** on a
doubled URL and **stopped including un-playable catalogue tracks**; Apple's user-auth flow **stopped
rejecting the developer token**; and email verification **stopped sending duplicate welcome emails**.
A late, docs-titled commit also landed the **Apple-id + ISRC de-duplication** that keeps playlists
free of the same recording while preserving the target length. The layered architecture and

## 3 · `resomix-similarity-open` — Hetzner Media / Similarity Server (`:8004`)

**Window:** 2026-07-13 → 2026-07-23  ·  **Commits:** 8.
**Role:** FAISS similarity + HLS segments / previews / peaks; internal-API + edge-token serving.

### 🚀 New Functionalities
- **Playlist cover image management** (the media half of the custom-cover feature): store/serve a
  user-uploaded cover **by playlist uuid**, kept separate from track covers — partner-scoped paths,
  a public `GET /playlist-cover-image/` (edge-token), and internal `POST`/`DELETE /internal/
  playlist-cover` with Pillow validation (`85c7dbf`); dimension bounds set to **100–4000 px square**
  (`ef5596d`); `Pillow` added to `requirements.txt` (`4b20ba0`).
- **Production ops RUNBOOK** for the media box (`a0e66b1`).

### 🐛 Bug Fixes
- **Uploads only got a 30-second HLS window** (`944bd9d`): uploads now generate **full-track HLS
  segments** (`restricted=False`); the 30s mode is retained but no longer triggered. Peaks were
  already full-track. Covered by a new test (`cbbdb40`). *(Directly fixes uploads that cut off at
  ~30s on playback.)*
- **Replaced covers served stale** (`e4c2742`): playlist-cover responses switched from
  `max-age=60` to **`no-store, must-revalidate`**, so a re-uploaded cover shows immediately in the
  library and on the playlist page (the URL is identical across views, so any positive cache TTL
  served the old image).
- **numpy-2 / FAISS incompatibility** (`d361379`, terse "fix"): pinned `faiss-cpu 1.7.4 → 1.14.3` so
  the service runs on the box's numpy 2.x (the older FAISS crashed under numpy 2).

### 📋 Summary
Small but pointed: the media server gained the **playlist-cover** store/serve/validate endpoints and
had two real playback/serving bugs fixed — **uploads now stream the full track** (not a 30s clip) and
**replaced covers no longer serve from cache** — plus a dependency pin that keeps FAISS working under
numpy 2. A production RUNBOOK was added.

## 4 · `resomix-analysis-service` — Analysis Microservice (`:8010`)

**Window:** 2026-07-13 → 2026-07-23  ·  **Commits:** 4.
**Role:** audio → analysis pipeline (Celery), result store (Redis + durable), GPU-backed stages.

### 🚀 New Functionalities
- **Durable, long-term result retrieval** (`7477581`): completed analyses are persisted with **gzip
  compression** to a durable results dir and job statuses are **synthesized/reconstructed** so a
  result survives Redis-TTL expiry (previously a finished analysis vanished when its 24h Redis key
  expired). Added unit tests. *(This is the root fix behind the "reopened analysis 404→502" problem.)*
- **Operational RUNBOOK + dev steps** (`ab90f3f`).

### 🐛 Bug Fixes
- **Stale results in staging/production** (`153f6bf`): the by-filename **GPU-response cache**, the
  **sha256 content-hash dedupe index**, and **uploaded-audio retention** are now all gated to
  `env == "local"`. Non-local environments always compute fresh under their own `analysis_id` and
  drop the raw audio when done — so staging/prod can never serve a cached/deduped analysis.

### 🔧 Other / Small Changes
- **Leaf-genre cleaning in the semantics stage** (`d12a6fb`): the pipeline emits the leaf of a
  `Parent---Child` Discogs genre at the source, matching the Alwyzon-side clean-up.

### 📋 Summary
Four focused commits that hardened result durability and environment correctness: analyses now
**persist compressed and survive Redis expiry**, staging/production **never reuse cached or deduped
results** (fresh every time, raw audio discarded), and genres are cleaned to their leaf. A RUNBOOK was
added.
