5. Data Preservation: Backup Strategy for 22TB
Preserving 22TB of data is a non-trivial engineering challenge. "RAID is not a backup" is a mantra in systems administration; RAID protects against disk failure, but not against corruption, accidental deletion, or ransomware. Rights holders will require a robust Disaster Recovery (DR) plan.

5.1 Deduplication and Incremental Backup
Backing up 22TB raw data daily is impossible due to bandwidth and time constraints. The solution lies in content-addressable storage tools like Restic or BorgBackup. These tools break files into variable-length chunks and fingerprint them. If a file is moved, renamed, or only slightly altered (e.g., a metadata tag update), the software recognizes the existing chunks and only uploads the new unique data. This deduplication is highly effective for music libraries where multiple versions of a track might share identical audio data.

5.2 The 3-2-1 Strategy with Object Storage
The industry standard "3-2-1" rule implies: 3 copies of data, on 2 different media, with 1 offsite.
Copy 1: Live data on Hetzner storage volumes (MinIO).
Copy 2: Local snapshot on a separate Hetzner Storage Box (mounted via CIFS/SSHFS) for fast recovery.
Copy 3 (Offsite): Immutable backup stored in Backblaze B2.
Backblaze B2 is the recommended offsite target due to its economic model ($6/TB/month vs. ~$23 for AWS S3) and its compatibility with Restic. This provides a "cloud air-gap." Even if the Hetzner account is compromised and wiped, the data resides safely in a different provider's ecosystem.

5.3 Disaster Recovery and Restoration Time Objectives (RTO)
A critical metric in the DR plan is the Recovery Time Objective (RTO). Downloading 22TB over a standard 1Gbps connection would take days, potentially weeks, saturating the network. To address this, the technical response to labels should highlight the use of physical data transport services for emergency recovery. Backblaze offers the "Fireball" service, where they ship a 96TB NAS unit loaded with the backup data via overnight courier. This allows for data restoration at local network speeds (10Gbps), reducing the RTO from weeks to days. Explicitly mentioning this capability demonstrates operational maturity and foresight.
